## 2. Approved Human Decisions (`H030-001` through `H030-006`)

The following decisions are approved by the Sole Human Owner as the authoritative product, architecture, and governance baseline for Milestone v0.3.0:

### H030-001: v0.3.0 Milestone Scope Boundary (APPROVED)
> **Decision Text:** Authorize the v0.3.0 Organization Identity and Portal Alpha boundary: organization, party, directory, scoped authorization, and snapshot-oriented portal capabilities only. Defer later product behavior to v0.4.0.
- **Governing Focus:** Restricts Milestone v0.3.0 exclusively to organization modeling, party directory, fine-grained scoped authorization, and snapshot portal presentation. Advanced workflows, broader analytics, and deferred product features remain reserved for v0.4.0.
- **Directly Affected Issues:** Issue #74.

### H030-002: Organizational Hierarchy and Party Modeling (APPROVED)
> **Decision Text:** Adopt Tenant -> Company -> Business Unit -> Project -> Site -> Area as the organization hierarchy. Model contractors and subcontractors as sponsored, bounded participation relationships. Preserve historical attribution; no irreversible deletion is authorized.
- **Governing Focus:** Formalizes canonical six-level hierarchy structure. Mandates that third-party contractors and subcontractors must operate under sponsored, bounded scopes. Strictly forbids irreversible data deletion to preserve complete historical and compliance attribution.
- **Directly Affected Issues:** Issue #75, Issue #80, Issue #83.

### H030-003: Authorization Invariants and Delegation Rules (APPROVED)
> **Decision Text:** Adopt default-deny, scope-bound authorization with explicit assignment, conflict checks, source-authority validation, expiry, and audit. Delegation is never implicit and must be time-bounded.
- **Governing Focus:** Establishes mandatory default-deny authorization policy across all operations. Requires explicit role assignment, conflict detection, source-authority verification, bounded lifetimes/expiry, and comprehensive audit trails. Prohibits implicit delegation; all delegated access must be explicit and strictly time-bounded.
- **Directly Affected Issues:** Issue #75, Issue #90, Issue #92.

### H030-004: Local Identity and User Lifecycle Baseline (APPROVED)
> **Decision Text:** Use local identity and synthetic users for v0.3.0. External users require a sponsor, explicit validity, and renewal. No external identity-provider activation, trusted-device claim, or offline-access authorization is granted.
- **Governing Focus:** Mandates local synthetic identity mechanisms for all internal development and alpha qualification. External user identities require explicit organizational sponsorship, bounded validity, and manual renewal. Prohibits external IdP integration (OIDC, SAML, Azure AD, Okta), trusted-device credentials, and offline access claims.
- **Directly Affected Issues:** Issue #76, Issue #94, Issue #95.

### H030-005: Privacy, Data Minimization, and Directory Visibility (APPROVED)
> **Decision Text:** Use data minimization and exact-scope directory visibility. Prohibit cross-project discovery and use of customer or real personal data. Use synthetic or redacted data only.
- **Governing Focus:** Enforces strict data minimization and exact-scope directory access. Prohibits cross-project user or entity discovery. Strictly forbids ingestion, storage, or processing of live customer data or real personal identifiable information (PII). All testing and fixtures must use synthetic or redacted data only.
- **Directly Affected Issues:** Issue #75, Issue #76, Issue #87, Issue #94, Issue #102, Issue #107.

### H030-006: Snapshot-Only Portal Publication Architecture (APPROVED)
> **Decision Text:** Use snapshot-only, approval-controlled portal publication. Keep public fixtures non-indexed and separate from internal routes. Prohibit live operational queries and external public-route activation.
- **Governing Focus:** Restricts the customer/public portal architecture to static, approval-governed snapshot publication. Public fixtures must remain unindexed by search engines and decoupled from internal API routes. Prohibits live operational database querying from the portal and forbids public network route activation.
- **Directly Affected Issues:** Issue #75, Issue #76, Issue #99, Issue #102, Issue #107.

## 5. Local-Synthetic Operating Boundaries and Prohibitions

In accordance with decisions `H030-001` through `H030-008`, Milestone v0.3.0 operates within strictly defined non-negotiable boundaries:

- **Synthetic Engineering Data Only:** All fixtures, seeds, and test scenarios must utilize synthetic, fictionalized, or redacted test records. Committing or processing actual employee identities, government IDs, corporate secrets, or live customer data is strictly prohibited.
- **Zero External Identity Activation:** Authentication is provided solely by the local in-memory/mock identity adapter. Network connections to external OAuth/OIDC providers are prohibited.
- **Zero Public Route / CDN Activation:** No external public domains, DNS records, public cloud routes, or CDN endpoints may be configured or exposed.
- **No Live Portal Queries:** The portal operates exclusively on pre-generated, approval-controlled snapshot records. Direct querying of live operational transactional schemas from the portal layer is prohibited.
- **No Production Release or Deployment:** Creating release tags, publishing production packages, signing binaries, or initiating production deployments is strictly forbidden.
