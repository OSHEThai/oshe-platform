## 3. Evidence-Backed Known Limitations

The following limitations represent proven, documented architectural boundaries of Milestone v0.2.0. Each limitation is linked directly to governing ADRs, test suites, and configuration invariants:

### LIM-01: Bounded Local-Synthetic Profile Execution Only
- **Description:** The system kernel operates exclusively within the approved single-node local Docker development profile (`deploy/local/compose.dev.yaml`) and local process containers.
- **Evidence Link:** `ADR-0002`, `ARC-V020-SYSBASE-001`, `tests/test_v010_i010_local_stack_contract.py`.
- **Operational Boundary:** Multi-node database clustering, container orchestration (Kubernetes), geo-distributed deployments, and cloud load balancers are unobserved, untested, and strictly out of scope.

### LIM-02: In-Memory / Local Synthetic Identity Adapter Exclusivity
- **Description:** User authentication and identity claim issuance are handled exclusively by the local synthetic identity adapter (`modules/identity-authorization/local_identity.go`).
- **Evidence Link:** Decision `V020-D11`, `SEC-V020-ASSUR-001` (TB-03), `modules/identity-authorization/negative_controls_test.go`.
- **Operational Boundary:** Zero integration with external Identity Providers (OIDC, SAML 2.0, Microsoft Entra ID, Okta). Network egress to external authorization servers is prohibited.

### LIM-03: Single-Node S3 Object Storage Adapter
- **Description:** Binary evidence persistence is validated using the local in-memory storage adapter (`MemoryStorageAdapter`) and single-node SeaweedFS (`http://127.0.0.1:8333`).
- **Evidence Link:** Decision `V020-D12`, `modules/files-evidence/storage_adapter_test.go`, `deploy/local/compose.dev.yaml`.
- **Operational Boundary:** Commercial cloud S3 services (AWS S3, Google Cloud Storage), cross-region bucket replication, S3 Object Lock compliance legal hold, and Customer Managed Encryption Keys (CMEK) via cloud KMS are unobserved and unverified.

### LIM-04: Deferred Mobile Edge Synchronization Daemon
- **Description:** Offline checklist instantiation, template snapshot retention, and causal conflict detection are architecturally enforced in `MOD-CFG` and `MOD-WFA`. However, the background device synchronization daemon and wireless mesh transport are deferred.
- **Evidence Link:** `SEC-V020-ASSUR-001` (TB-08), `docs/releases/v0.2.0-release-boundary.md`, `modules/configuration-checklist/template_lifecycle_test.go`.
- **Operational Boundary:** Mobile SQLite local databases, background delta synchronization workers, and physical Android/iOS edge clients are deferred to Milestone v0.4.0.

### LIM-05: In-Memory Request Contract and API Gateway Boundary
- **Description:** The REST/HTTP gateway layer (`apps/api`) is validated via in-memory Go contract tests and synthetic schema fixtures (`contracts/api`).
- **Evidence Link:** `tests/test_api_contracts.py`, `contracts/api/`, `apps/api/`.
- **Operational Boundary:** Publicly exposed HTTP daemon listeners with reverse proxy TLS termination, Web Application Firewalls (WAF), DDoS mitigation, and public DNS routing are unobserved and unconfigured.

### LIM-06: Synthetic Engineering Data Exclusivity
- **Description:** All verification fixtures, database seed records, and test scenarios operate exclusively on synthetic, redacted, low-risk engineering data.
- **Evidence Link:** Decision `V020-D05`, `repo-manifest.yaml`, `tests/fixtures/synthetic/`.
- **Operational Boundary:** No live customer operational inspection data, real worker personal identifiable information (PII), national identification numbers, medical records, or legal-privileged materials have been ingested or tested.

## 5. Residual-Risk Register

The residual-risk register identifies technical, operational, and environmental risks that cannot be eliminated solely through local-synthetic testing. **No residual risk is accepted by this document or by the AI agent role.** All entries are compiled for evaluation by the Sole Human Owner under deferred human gates:

| Risk ID | Risk Category | Risk Description | Inherent Risk | Mitigating Controls in v0.2.0 | Residual Risk Rating | Deferred Human Gate for Acceptance |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **`RSK-01`** | Infrastructure / Storage | **S3 API Compatibility Drift:** Local SeaweedFS S3 emulation may exhibit edge-case API differences compared to commercial AWS S3 or MinIO in production. | HIGH | S3 client uses standard AWS SDK v2; storage adapter tests assert bit-level SHA-256 parity and key prefixing. | **MEDIUM** | **`HCOM-001`** (Cloud Provider Route Qualification Gate) |
| **`RSK-02`** | Security / Auth | **Third-Party IdP Token Expiry During In-Flight Inspection:** When integrating live OIDC, long-duration offline inspections may submit tokens that expired while the user was in an area without network connectivity. | HIGH | Kernel enforces real-time revocation in `RevocationManager` and records monotonic timestamps in audit logs. | **MEDIUM** | **`H020-007`** (Security & Residual-Risk Gate) |
| **`RSK-03`** | Performance / Concurrency | **Database Connection Contention Under Concurrent Alpha Load:** Monolithic PostgreSQL schema isolation may face connection starvation under concurrent batch reporting queries. | MEDIUM | Reporting queries marked strictly non-authoritative; outbox worker uses bounded polling (`SKIP LOCKED`); database connection pooling configured in `pgx`. | **LOW-MEDIUM** | **`H020-005`** (Gate C Alpha Entry Qualification) |
| **`RSK-04`** | Data Safety / Edge | **Mobile Device Clock Drift Affecting Offline Audit Ordering:** Unsynchronized client clocks on disconnected mobile devices could submit timestamps out of sequence with server receipt time. | MEDIUM | Kernel records both client-reported timestamp and monotonic server receipt timestamp in `MOD-REC`; blind LWW is strictly forbidden (`HAZ-001`). | **LOW** | **`H020-007`** (Product Safety & Residual-Risk Gate) |
| **`RSK-05`** | Domain / Quality | **Synthetic Inspection Fixture Simplicity vs Real-World Hazard Diversity:** Synthetic checklists in `v020-walking-skeleton-fixtures.json` may not fully anticipate complex multi-section industrial inspections. | MEDIUM | Template schemas use versioned, declarative JSON definitions (`MOD-CFG`); M0-M2 non-destructive migration verified. | **LOW-MEDIUM** | **`H020-005`** (Gate C Alpha Qualification) |

## 6. Explicit Catalog of Missing and Unobserved Inputs

To guarantee transparent governance and prevent unjustified claims of readiness, this register explicitly itemizes all technical components, operational environments, and governance records that remain **missing, unobserved, or deferred**:

### 6.1 Unobserved Production Infrastructure Components
1. **Production PostgreSQL Cluster:** High-availability multi-node clustering (Patroni / streaming replication), database connection pool proxies (PgBouncer), and Row-Level Security (RLS) enforcement at the database role level.
2. **Distributed Cloud Object Store:** High-durability distributed S3 storage clusters, cross-region replication, customer-managed encryption key (KMS) integration, and S3 legal hold compliance.
3. **Production Message Broker Cluster:** Multi-node NATS JetStream clustering with TLS mutual authentication (mTLS), hardened subject authorization, and multi-datacenter stream mirroring.
4. **Live HTTP Gateway Infrastructure:** Production HTTP daemon listeners (`apps/api`), reverse proxy TLS termination, Web Application Firewall (WAF) rule sets, rate-limiting engines, and DDoS defense.

### 6.2 Unobserved Third-Party Integrations and Provider Routes

2. **External Notification Services:** SMTP email relays, SMS dispatchers, and mobile push notification delivery (Apple APNs / Google FCM).
3. **Mobile Native Applications:** Compiled Android (`.apk`) and iOS (`.ipa`) native application binaries operating on physical mobile hardware.
