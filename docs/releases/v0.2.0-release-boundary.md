# v0.2.0 Release Boundary and Walking Skeleton Specification

## 1. Governance Basis & Overview

This document specifies the operational boundaries, walking-skeleton critical path, module ownership, and assurance traceability for **`v0.2.0 — Shared Platform Kernel`**.

- **Governing GitHub Issue**: [OSHEThai/oshe-platform Issue #36](https://github.com/OSHEThai/oshe-platform/issues/36) (`[V020-I001] Define v0.2.0 Release Boundary and Walking Skeleton`).
- **Governing Human Decision**: **`HDEC-V020-GATE-B-APPROVAL-051`** (Sole Human Owner approval of v0.2.0 Gate B Entry and Local-Synthetic Implementation Baseline, carrying forward `HDEC-V010-I009-H010-003` and `HDEC-V010-V020-IMPLEMENTATION-ENTRY-010`).
- **Release Classification**: `INTERNAL_ENGINEERING_ALPHA`.
- **Purpose**: Deliver the reusable shared platform kernel and capability engines required by the OSHE Inspect walking skeleton and future compatible product suites under modular-monolith architecture (`ADR-0001`) and shared codebase deployment profiles (`ADR-0002`).

---

## 2. Approved Walking Skeleton Critical Path

The v0.2.0 shared kernel is strictly bounded by the end-to-end execution of the ten-step OSHE Inspect walking skeleton:

```text
1. Tenant & Organization Context
   ↓
2. Project & Site Context
   ↓
3. Trusted Identity & Scoped Membership
   ↓
4. Checklist / Form Version Draft, Review, Approval & Publication
   ↓
5. Executable Instance & Deterministic Workflow Execution
   ↓
6. Immutable Evidence Storage & Verification
   ↓
7. Finding & Corrective Action Lifecycle
   ↓
8. Review, Reinspection & Closure
   ↓
9. Deterministic Report Generation & Export
   ↓
10. Complete Audit Reconstruction & Event Verification
```

## 3. Walking Skeleton Step Traceability Matrix

Each walking-skeleton step maps to an authoritative module family, mandatory risk/control requirements, and verification test families:

| Step # | Walking Skeleton Step | Owner Module Family | Mandatory Risk & Governance Controls | Verification Family |
|---|---|---|---|---|
| **1** | Tenant & Organization Context | `MOD-ORG` (Organization and Tenancy) | Default-deny tenant isolation; strict tenant ID scoping on all reads/writes; no cross-tenant query leakage (`V020-D07`). | Tenant-isolation negative tests, boundary regression suite. |
| **2** | Project & Site Context | `MOD-ORG` (Organization and Tenancy) | Hierarchy constraints; site operational bounds; scoped identifier validity (`V020-D09`). | Scoped context validation, relational integrity checks. |
| **3** | Trusted Identity & Scoped Membership | `MOD-IAM` (Identity and Authorization) | Two-level membership (`ADR-0003`); local development identity adapter/emulator only (`V020-D11`); external IdP prohibited. | RBAC/ABAC permission envelope tests, local auth emulator tests. |
| **4** | Form Draft, Review & Publication | `MOD-CFG` (Configuration and Checklist) | Immutable published versions; schema validation; cryptographic hash of form definition (`V020-D09`). | Schema registry compatibility tests, lifecycle state machine tests. |
| **5** | Executable Instance & Workflow | `MOD-WFA` (Workflow and Action) | Deterministic state transitions; idempotent action handling; transactional outbox for event dispatch (`V020-D04`, `V020-D12`). | Workflow regression tests, failure injection and recovery tests. |
| **6** | Immutable Evidence Storage | `MOD-EVD` (Files and Evidence) | SHA-256 integrity digest; adapter-first SeaweedFS S3 storage (`V020-D12`); immutable retention; zero client direct-access keys. | Evidence integrity verification, tamper-detection negative tests. |
| **7** | Finding & Action Lifecycle | `MOD-WFA` (Workflow and Action) | Strict finding-to-inspection association; mandatory state transitions (Open $\to$ Assigned $\to$ Remediation $\to$ Verify). | Finding state transition tests, outbox event dispatch tests. |
| **8** | Review, Reinspection & Closure | `MOD-WFA` (Workflow and Action) / `MOD-REC` (Records and Audit) | Explicit inspector and reviewer role separation; tamper-evident completion timestamps; non-reversible closure. | Role segregation validation, reinspection workflow tests. |
| **9** | Deterministic Reporting & Export | `MOD-REP` (Reporting, Localization and Feature Control) | Local deterministic report renderer (`V020-D12`); zero external/cloud renderer dependencies; consistent pagination/layout. | Deterministic snapshot tests, rendering output contract QA. |
| **10** | Complete Audit Reconstruction | `MOD-REC` (Records and Audit) / `MOD-EVT` (Events, Outbox and Jobs) | Append-only event log; causal ordering via NATS JetStream outbox; full state reconstruction from events (`V020-D06`, `V020-D09`). | Audit log replay verification, event-stream reconstruction tests. |

## 4. Explicit Non-Goals (Out of Scope for v0.2.0)

To maintain focus on the internal engineering alpha, the following capabilities are explicitly deferred:

1. **Production Deployment & Cloud Topology**: No production multi-region SaaS, production cloud infrastructure, or multi-cluster Kubernetes deployment.
2. **External Identity Providers**: No production SAML 2.0, OpenID Connect enterprise federation, or third-party OAuth2 activation (`V020-D11`).
3. **External AI Route Activation**: No external AI provider invocation or route activation; AI runtime remains local/mock or deferred (`H010-004`, `H010-007`).
4. **Marketplace & Dynamic Extensions**: No third-party extension runtime, plugin store, or dynamic external code execution (`ADR-0004`).
5. **High-Risk Domain Packages**: No medical records, Permit to Work (PTW), Lockout/Tagout (LOTO), emergency command, or legally protected safety decisions.
6. **Populated Legal/Regulatory Catalogs**: No exhaustive multi-jurisdiction compliance libraries.
7. **Full Edge / Air-Gapped Appliance Qualification**: No disconnected field hardware appliance qualification; site-edge local caching is internal mock only.

## 5. Local-Synthetic Boundary & Excluded Authorities

### Local-Synthetic Operating Envelope
- **Data Boundary**: Operates strictly on synthetic, simulated, or redacted low-risk engineering data (`V020-D05`).
- **Prohibited Data**: Customer data, real participant data, production data, medical information, security-case records, and production secrets are strictly prohibited.
- **Infrastructure Baseline**: Local containerized stack using Docker Compose (`HDEC-V010-I009-H010-003`): Go 1.26.5, React 19.2.8, PostgreSQL 17.11 / PostGIS 3.6.4, Meilisearch 1.51.0, Valkey 9.1.1, SeaweedFS 4.29, NATS JetStream 2.14.5.

### Excluded Authorities (Strictly Prohibited)
In compliance with `HDEC-V020-GATE-B-APPROVAL-051` and `LEASE-V020-I001-RELEASE-BOUNDARY-057`, the following authorities are excluded:
- Production deployment or public availability commitments.
- Customer or production data processing.
- Production credentials or release signing.
- External identity, notification, external AI provider, or paid-service activation.
- Force push, repository deletion, or credential/account/payment changes.
- Residual-risk acceptance or final release decision.
