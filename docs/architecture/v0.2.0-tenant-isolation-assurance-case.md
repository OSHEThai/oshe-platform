# V0.2.0 Tenant-Isolation Assurance Case

Document ID: `SEC-V020-ASSUR-001`
Status: `PROVISIONAL_LOCAL_SYNTHETIC_ONLY`

## 1. Scope and authority boundary

This assurance case records the V0.2.0 local-synthetic design boundary. It is grounded in `SEC-V020-THREAT-001` (the V0.2.0 threat model, privacy assessment and hazard log) and `EVD-V020-DISPOSITION-001` (the known-limitations, defect-disposition and residual-risk register). It is not runtime qualification, a release recommendation, or residual-risk acceptance.

## 2. System context and data flow

```text
[Inspector device] -- untrusted request --> [API boundary]
       --> [tenant and identity controls] --> [domain modules]
       --> [private module data / evidence store] --> [derived reports]
       --> [audit and event evidence]
```

The authoritative flow derives tenant context server-side, checks identity and policy before domain work, binds records and evidence to that tenant scope, and emits auditable domain events. Derived reports are non-authoritative. `SEC-V020-THREAT-001` §2.2 and §5 are the source for the abuse-case and critical-function controls in this flow.

## 4. Tenant-isolation controls

Controls are organized in four planes:

- Control plane: verified claims establish tenant context; callers cannot override it.
- Execution plane: policy and workflow checks default deny; a feature flag cannot grant authority.
- Data plane: module ownership, tenant prefixes, integrity digests and migration ordering constrain data access and mutation.
- Observability plane: audit records retain evidence while diagnostics avoid foreign-tenant disclosure.

These controls correspond to `SEC-V020-THREAT-001` abuse cases AC-01 through AC-07 and hazards HAZ-001 through HAZ-010. They are design and local-test evidence references only, not assertions of a live deployment.

## 6. Threat, control, and negative-test mapping

AC-01 maps to tenant-header override and prefix-collision denial; AC-02 to immutable published-template denial; AC-03 to digest mismatch and cross-tenant evidence denial; AC-04 to cross-tenant reporting denial; AC-05 to outbox rollback, deduplication and poison quarantine; AC-07 to workflow rollback and separation-of-duties denial. The applicable acceptance references are listed in `SEC-V020-THREAT-001` §§2.2, 4.3 and 5. Any runtime or provider verification remains unobserved unless independently qualified.

## 7. Explicitly unobserved boundaries

The following remain `[UNOBSERVED]`, following `EVD-V020-DISPOSITION-001` §6: clustered PostgreSQL and role-level RLS; distributed object storage and customer-managed keys; clustered NATS with mTLS; public HTTP listeners, WAF and DNS; external identity providers; production notification relays; and physical mobile-edge synchronization.
